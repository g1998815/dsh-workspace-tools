### 0.4 全局约束

- 路径语义：RPC/`ctx.fs` 层 relPath 恒为 POSIX `/` 分隔；Windows 侧 `node:path` 自动按 win32 语义；**不硬编码分隔符**（file-tree.js:209 的 `split("/")` 是 POSIX rel，保留）。
- 编码：git 输出已 `utf8` + quotepath=false；`execFile` 不经 shell，不受控制台代码页影响。
- CRLF：`parseDiff` 按 `\n` split；git diff 输出内部统一 LF；untracked 全文视图的 `\r` 在 `whiteSpace:pre` 下不显示。**若真机发现行尾异常再补 `\r` 剥离**，不预先改。

**Files:**
- Modify: `lib/services/console.js`（win32 guard）
- Modify: `test/console.test.js`（+1 用例）
- 无 client 改动（`src/components/console.js` 已有 catch → `panelError` 渲染路径）

**Interfaces:**
- Produces: `createShellSession` 在 win32 抛 `{ code: "unsupported-platform", message: "Windows 暂不支持控制台" }`。
- Consumes: `platform()`（`node:os`，已 import）。

- [ ] **Step 1: 写失败测试**

```js
// test/console.test.js 追加
test("createShellSession: win32 throws unsupported-platform (M5)", async () => {
  await assert.rejects(
    createShellSession({ spawnTerminal: async () => { throw new Error("should not be called"); } }, { cwd: "C:\\ws", platform: "win32" }),
    (e) => e.code === "unsupported-platform",
  );
});
```

> 需给 `createShellSession` 加 `platform` DI 参数（默认 `platform()`），否则非 win32 机器无法单测。签名：`createShellSession(deps, { cwd, rows, cols, platform: plat = platform() } = {})`。**在 Windows 上执行时 `platform()` 本身就是 win32**——Step 3 后可直接 RPC 真机验证（Task 3 Step 3 控制台项）。

- [ ] **Step 2: 跑测试确认失败**

Run: `node --test test/console.test.js`
Expected: FAIL（无 guard）。

- [ ] **Step 3: 实现**

```js
// lib/services/console.js —— createShellSession 开头：
export async function createShellSession(deps, { cwd, rows = 80, cols = 24, platform: plat = platform() } = {}) {
  if (plat === "win32") {
    // M5：Windows PTY 后端未实现（spawnTerminal win32 必抛）——显式结构化降级
    throw { code: "unsupported-platform", message: "Windows 暂不支持控制台" };
  }
  // ... 原逻辑不变
}
```

- [ ] **Step 4: 语法 + 全量测试**

Expected: check 通过；86 全绿（85 + 1）。
